# Cursors — 2026-11-10

A brainstorm on joining cursors, for the Cells plan's
`cells-freeze.cursors`
([`../plans/Cells_2026-11-09.md`](../plans/Cells_2026-11-09.md)), held at
the maintainer's request (2026-11-10): "we'll need to attend carefully to
discovering when cursors must connect aux-to-aux in the copy's net. I.e.
if you copy a lam for identity function, we'd naively have two
disconnected cursors if following the recipe you described. The question
is how to join cursors robustly and efficiently. Brainstorm a few ideas,
asking Fable as well."

Two reviewers brainstormed independently: the agent, here, and a Fable
sub-agent, whose brainstorm is kept as written in
[`CursorsFable_2026-11-10.md`](CursorsFable_2026-11-10.md). The last
section compares them. This review proposes; the maintainer decides.

## The problem

The draft recipe walks from the source's interface, copies each node
whose principal port faces up, and leaves a cursor at every port it
cannot copy through. The identity function `\x -> x` is one Fn node
whose result port (−) is wired to its own variable port (+): a wire
between two auxiliary ports. The recipe copies the Fn, finds no node
behind either auxiliary port, and leaves two cursors that are really one
wire. The same happens wherever a wire joins two auxiliary ports:

- a variable passed straight to the body;
- a copy fan's input facing a variable (a variable used twice);
- an operator's argument facing a variable;
- a pending pair's argument facing a variable, `\x -> (\y -> y) x`. The
  pair reduces to a wire from the result to the variable, which every
  copy must see as its own wire.

## An observation: every net is a forest of principal trees

Every node has exactly one principal port, and its peer is one other
port. Follow each node's principal to the node that peer belongs to. The
relation forms trees (Lafont's decomposition of a net), and each tree is
rooted in one of three places:
- the interface;
- an active pair, two principals facing each other;
- a cycle of principals each facing an auxiliary port, a deadlock that
  never reduces.

A node can be rewritten only once its principal meets a principal. So a
node whose principal faces an auxiliary port of a node that will never
be rewritten will never be rewritten either.

So *finished* has an exact meaning: the tree of the interface. In a
source, the function's own Fn is never applied, since copies are applied
instead. Everything waiting on its variable is therefore in the
interface's tree and finished:
- a copy fan whose input faces the variable;
- an operator waiting on the variable's data.

Everything in a tree rooted at an active pair is unfinished.

This makes the identity's two "cursors" no cursors at all: the Fn and
its self-wire are both inside the finished tree.

## Ideas

**C1. Copy the finished tree as a graph, with a map.** Copy every node
of the interface's tree, recording the copy of each source node in a map
indexed by node. Then, for each auxiliary port of a copied node, look at
its peer:
- the peer is a port of a copied node: link the two copies, each wire
  once;
- the peer is an auxiliary port of an unfinished node: one cursor.

The identity comes out as one Fn wired to itself. A splice already keeps
such a map (`Sp{h, map}` in `glam/splice.bend`). The cost is a walk and
a map over the finished nodes. It leaves alone wires that cross into
unfinished trees, which the next ideas handle.

**C2. A cursor is a boundary wire, grouped by the tree it enters.** The
wires crossing between the finished tree and one unfinished tree are
that tree's boundary. They come in two directions:
- *outbound*: the unfinished tree provides, such as a pending
  application's result feeding the body;
- *inbound*: the finished part provides and the unfinished tree
  consumes, such as `x` in `\x -> (\y -> y) x`.

A copy keeps one record per unfinished tree it reaches, mapping each
boundary wire to the copy's own port: a *group*. The tree reduces once,
in the source, its inbound wires being free wires there. Materializing
its result into a copy maps those inbound wires to the group's ports.
Three outcomes:
- a result that is finished structure is copied;
- a result that is a wire straight to an inbound boundary joins two of
  the copy's ports: the maintainer's aux-to-aux case, decided when the
  source decides it;
- a result still pending becomes a cursor in the same group.

This is the "residue that reaches a parameter" seen correctly: the
unfinished tree is shared, and the copy supplies its inputs. Cost: a
group per unfinished tree reached, and a port per boundary wire. Open: a
tree whose reduction must have the data of an inbound wire stops there.
That part becomes finished structure in the source, waiting on a free
wire, so it is copied per copy, rightly, since its work needs the
copy's input.

**C3. Anchors in the source.** Cut each boundary wire in the source with
an anchor node, a node of its own kind with no rules of its own but one:
two anchors meeting record that their cursors are one wire. Cursors then
name anchors, ids stable under reduction, rather than a node and port
that a rewrite may move. The join is discovered by the reduction itself,
when an annihilation or a beta leaves two anchors facing. Kernel: a kind
and a rule, under the laws. It pairs naturally with C2. An anchor's
polarity is fixed by the wire it cuts.

**C4. Union-find over a copy's cursors.** Joins can chain: a wire runs
through several pending pairs before it reaches an inbound boundary, and
each pair reduces at its own time. The copy keeps its cursors in a
union-find: the source reports "boundary a is now boundary b", the copy
unions them, and materializing links ports through the representative.
Joins are lazy (found when demanded) and cost near-constant time each.

**C5. Settle the boundary before copying.** Under fuel, reduce the cheap
pairs that touch the boundary first: annihilations, a beta whose
argument is a variable, fan meeting fan. Early evaluation is an
optimization (`early-evaluation-optimization`). Most aux-to-aux joins,
the identity redex among them, then vanish before any copy is taken, and
cursors remain only where real work is pending. It reduces how often
joins happen without solving them. It is cheap, and measurable on the
ladder.

**C6. A residue with inputs is a function.** At materialization,
abstract each unfinished tree over its inbound wires: one Fn per inbound
wire, so the residue becomes a closed function. The copy applies it to
its own ports, and joins happen in the copy by a beta, an ordinary
interaction. The abstracted residue is itself a live source, copied by
the same mechanism, so the scheme is recursive and needs no join
protocol. Its cost is an Fn and an Ap per inbound wire per copy, and the
abstraction must not move levels inside the residue. Of all six it is the
closest to "lambda lifting the residue", and it keeps the source unaware
of copies.

**C7. In one net, a cursor is a fan.** If a source and its copies share
a net, a cursor is a fan at a fresh level, and joins are fan-fan
annihilations, which GAL already pairs. This is the in-net limit of
cursors: optimal sharing, at the cost "keeping the original separated"
was meant to avoid. It serves as a reference for tests, since the linked
build already does it.

## Levels

Each group records the copy's level offset, as a splice raises a
template. Inbound ports are at the copy's levels, and the source's free
inbound wires carry the source's. Materializing a result raises it by
the offset, as `glam/splice.bend` does. C6 adds a level question of its
own: the new Fn for each inbound wire must sit at the residue's level
so that nothing inside it moves.

## The agent's leaning, before the comparison

C1 with C2 is the baseline, and is needed by every idea: finished as the
interface's principal tree, a graph copy with a map, and cursors grouped
by the unfinished tree they enter. For joins, the agent first leaned to
C6 over C3 with C4, since C6 adds nothing to the kernel.

The comparison below withdraws that leaning. C6 cannot be built as
written: cutting an inbound wire to abstract the residue changes the
source's finished part. If the Ap that applies the abstraction is placed
in the source, it pairs with the new Fn at once and undoes the
abstraction.

## Experiments that decide

Library nets, each materialized twice and compared after normalization
with a whole copy (where the net terminates):
- the identity;
- `\x -> (\y -> y) x` (a join made by a pending pair);
- `\f -> \x -> f x x` (a variable through a fan);
- `\x -> K x Ω` (a pending pair that never finishes and an inbound
  wire);
- a chain of k identity redexes (joins through several pairs).

For each, count cursors, groups, joins, nodes copied and interactions
at k, 2k and 4k. Then F2's families in the ladder's sharing check.

## The maintainer's answers (2026-11-10)

To the five questions, in order:
1. "In the Rust implementation, we determined 'finished' by principal
   ports, but if you can determine what can be copied based on polarity
   or other local analysis, that seems acceptable. We might broadly
   define a source node as something we can materialize into the copy
   when it can only interact after materialization. So the trick is to
   determine this efficiently."
2. "IIUC, you're describing a sort of inverted materialization with
   anchors of some form. This might generalize to copying the interface
   node and pushing some interactions into the source net, running them
   there. ... I'd hesitate to modify the source nets because it becomes
   messy for diagnostics and doesn't align with 'freezing' source nodes
   into freely copyable templates."
3. "There's no problem having all node kinds in the rule table."
4. The Rust bootstrap joined cursors, at one point through "a table of
   logical copies or 'observers' of the runtime net ... Rather
   expensive and awkward, so I wonder if a simpler solution is viable."
5. The Rust bootstrap forced the deeper net to lower into the host,
   "the argument is that there may be more computations that can be
   shared through the intermediate net". Following deep cursors needs a
   proof that it loses no sharing, and then rests on performance.

The Cells plan records them under `cells-freeze.cursors`. On the second,
the anchors as proposed sit in the copy, never in the source, and no
copy's interaction runs in the source; that reading is to be confirmed.

## Comparison with the second reviewer

The second reviewer's brainstorm offers five ideas:
1. nodes then links, with placeholders by polarity and a per-copy table
   of positions, joined when the copy pulls;
2. forwarding in the source, keyed by copy, pushed to every copy;
3. the source numbering its frontier, with dense ids or boundary nodes;
4. a pairs-only residue, joined by the rule's external index;
5. cursors as fans.

**Where the two agree:**
- **Finished is a fixpoint, not the order a walk reaches nodes in.**
  The agent states it as the interface's principal tree; the second
  reviewer states it as "a node is finished when its principal port
  faces the interface or an aux port of a finished node". Both readings
  make the identity a whole copy. The second reviewer adds a sharper
  case: a first-contact walk leaves five cursors in `\f -> \x -> f x x`,
  which has none.
- **Copy as the splice does, nodes then links through a map** (C1, its
  idea 1). The aux-to-aux wire inside the finished part is then an
  ordinary link, and two cursors never sit on one wire.
- **The real join is across time.** A later materialization reaches a
  port the copy already holds. The second reviewer names the two kinds
  by polarity:
  - at a *negative* position the copy awaits a value; this is the
    draft's cursor, a data node holding a handle, met as a need is met;
  - at a *positive* position the copy supplies a value, its argument,
    to pending work in the source; a placeholder of a new kind holds it,
    an anchor.

  These are C2's outbound and inbound wires.
- **Ports or fans remain the fallback and the oracle** (C7, its
  idea 5): the linked build already shares this way.

**What the second reviewer adds:**
- **Finishedness is monotone under reduction.** A rewrite rewires only
  the outer peers of its pair, and a finished node is never in a pair,
  so a finished node stays finished, and a wire between two finished
  nodes is never rewired. Hence a later materialization reaches an
  already-copied node only at a former cursor position, which bounds
  every join table by the number of cursors. It proposes this as a law
  before any building. It names one hole: control fusion after a rewrite
  composes a new lift into the one it faces and frees the new one
  (`fl.fuse` in `spike/net.bend`: "p stays, l goes"). That can change a
  finished lift's offset after a copy took it, so fusion must be
  refused across the frontier, or a boundary node must stand between
  them. Whether the kernel's own fusion (`fuse-control-runs`) does the
  same is to check.
- **Placeholders threaded per copy.** A copy's placeholders are threaded
  through their spare word and scanned at a join, with no table and
  nothing in the source. This stays correct when a fan copies the copy,
  because the fan's rule duplicates each placeholder and each half is
  found by its own net's scan.
- **Demand's state 7, reinterpreted.** A task from a cursor that walks
  into the finished part meets what demand reports today as "a variable
  demanded outside its function's body" (state 7, `fw.scan` in
  `spike/kdemand.blend`). It must become "frontier reached,
  materialize".
- **Push is rejected.** Forwarding kept in the source (its idea 2) does
  work before demand, and breaks when a placeholder is duplicated.
- **A pairs-only residue loses sharing** (its idea 4). A node waiting on
  a pending result is copied before the result exists, so it reduces
  per copy.

**Where the two differ.** The agent's C3 (anchors cut into the source)
is the second reviewer's boundary-node variant of idea 3, kept by both
for later, should scans show in the counts. The agent's C4
(union-find) and C5 (settling the boundary first) are not in the second
brainstorm. C5 remains a cheap optimization. C4 is unneeded under
monotonicity, since joins never chain through finished nodes: a chain
of pending pairs resolves in the source before its result is
materialized.

**Synthesis, recommended.** Build in two halves, as the second reviewer
proposes.
1. **The walk's fix.** Compute finished as a fixpoint, copy nodes then
   links, and compare against whole copies of a reduced source on
   library nets: the identity, `\f -> \x -> f x x`, `\x -> (g c) x`.
2. **Placeholders by polarity.** A cursor data node at negative
   positions and an anchor kind at positive ones, threaded per copy,
   with demand from a position and state 7 reinterpreted. Move to
   dense ids only if scans show in the counts.

Before either half, state as laws that finishedness is monotone under
reduction and that a materialization meets the copy only at former
cursor positions.

**Questions for the maintainer,** merging both lists:
1. Is a node whose principal faces the source function's own variable
   (a fan or a lift under it, an operator waiting on its data) finished,
   and so copied and reduced per copy with the real argument? Both
   reviewers assume so, and it is what "only what waits on an
   argument's data is done per copy" says.
2. Never letting a copy's argument enter the shared source, holding it
   at an anchor until what consumes it is finished and copied: is that
   right?
3. A kind that never interacts, the anchor: is it acceptable in the
   rule table, with its proofs?
4. Did the Rust bootstrap join cursors, and how? Neither reviewer found
   it in the repository.
5. A cursor into a source that is itself a copy: chain through it, or
   forward to the deeper source with the offsets added?
