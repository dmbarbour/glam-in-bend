# Cells: definitions shared, recursion and objects

Drafted for the maintainer's review before building (the maintainer,
2026-11-09: "I think we need to work on cells next. But we should discuss
and review design in detail."). It proposes how the assembler the hello
ladder builds evaluates definitions as cells, and puts ten decisions to
the maintainer, each with its options and the agent's recommendation.
Nothing below is decided. Approved, it takes up for the assembler
HeapModel's `heap-cells`, `heap-freeze` and `heap-apply`
([`HeapModel_2026-10-27.md`](HeapModel_2026-10-27.md)), EvalSpike's
`spike-fixpoints` on glam's own programs, and the ladder's
`ladder-thunks` and `ladder-objects`
([`HelloLadder_2026-11-09.md`](HelloLadder_2026-11-09.md)), and it
answers part of `heap-model-review`.

## Re-scoped by the bridge (2026-11-09)

On "go" (the maintainer, 2026-11-09: "Alright, let's begin developing
this bridge"), this plan is re-scoped as `bridge-recursion` says
([`Bridge_2026-11-09.md`](Bridge_2026-11-09.md)), after the heap review:

- **Data definitions stay linked.** Within one net the static linker
  already evaluates a definition once, shared by fans, so `cells-data`
  waits until a value must be shared beyond its net.
- **A top-level function is a template.** The lowering makes it closed,
  each reference to a definition a leaf; demand meeting a leaf at an
  application splices a copy at the applying level (items 1 to 3). No
  freezing at run time: `cells-freeze` waits for function values made at
  run time, such as a partial application kept as a definition.
- **Cells only for the data a template refers to,** owned by the root
  heap and named relative to it, never with a meaning global to the
  run; the slice after recursion, built as `cells-data.root`.
- **The protocol's state is a task,** the single stack its first
  container, and a busy cell is a cycle only on the needing task's own
  chain (item 6).
- **Order:** `cells-splice` and `cells-recursion` first, through
  templates; then root cells; then `cells-objects`. A run with `--link`
  keeps today's static linking for a differential check.

## Where the ladder stands

- **Definitions are linked, not shared.** The core binds the definitions
  `asm.result` needs around its body as one binding group, nested in the
  order of their needs (`ladder-thunks.globals`). A definition is lowered
  into the net of each assembly that needs it, shared within that net by
  fans; a cycle is refused before any net is built.
- **Demand can already wait.** Where an application or an operator on
  demand's path meets a data node holding a handle (`VLazy`), demand
  stops needing it (state 2): `KS.need` reads the handle, `KS.resume`
  writes a value in its place and walks on (`spike/kstrat.bend`).
  Nothing in `glam/` makes a handle yet.
- **Functions live only inside a net.** A lambda lowers to a bind node at
  its level (`lambdas-lower-to-nets`, `lowering-uses-levels`); beta,
  `rule.ap(KFn, t)`, contracts only where the application's level is the
  bind's, and is stuck otherwise. No value holds a net: `VFun` is a
  builtin's partial application.
- **Templates load; nothing freezes.** `KN.load` makes a heap from a
  template (`T.Tpl`: nodes, links, root), the interface first, erasers
  made static links (`static-links-count-as-nodes`). `KN.reach` and
  `KN.sweep` find and free what the interface no longer reaches. Nothing
  turns a live net back into a template, or loads one into a running net.

## What cells must give

- One evaluation of each definition, shared by every reference, where
  each net now holds a copy.
- Recursion, direct and mutual, which the static linker refuses.
- `self` knots and lazy members for objects (`ladder-objects`), and
  modules as objects after them (item 7).
- A cached outcome. A cell keeps a program's outcome, an error value
  among them (`net-error-values`), never a machine's limit
  (`machine-limits-not-errors`): out of fuel ends a slice and the cell
  stays busy; out of memory is reported and caches nothing.

## The model proposed

Each top-level definition is a cell, named by a `U32` handle assigned
before any definition is lowered. A reference to another definition
lowers to a leaf, a data node holding `VLazy{h}`, one per occurrence: a
global is no variable of the net and needs no fans, and a local bound to
one copies the leaf as data. A cell is one of

    Cell = Recipe{t: Tpl}   -- the definition lowered, not yet forced
         | Busy             -- forced now: its net is a frame on the core's stack
         | Value{v: Val}    -- data, written once; an error value among them
         | Func{t: Tpl}     -- a function: its net frozen, the root a bind

The core forces depth-first. It runs the frame on top for a slice; on a
need for handle h it reads h's cell:

- **Value:** resume with the value.
- **Func:** splice a copy of the frozen net where the leaf stood (items 1
  to 3).
- **Recipe:** mark h busy, push a frame that loads its template, force it;
  when its demand ends, write the outcome to h, pop, serve the need.
- **Busy:** with one stack, a strict cycle; once tasks come, a cycle
  only if the cell's owner is the needing task's ancestor (item 6).

A demand ending with the root facing data makes a Value; facing a bind,
a Func (item 5); facing another leaf, it takes that cell's outcome,
forcing it first. `asm.result`'s cell is forced first. A cell is forced
at most once, so the stack is never deeper than the definitions are many:
a recursive call is a splice, never a frame.

## Decisions for the maintainer

1. **Applying a function value: splice or recipe.** The records disagree.
   `copy-reduced-function-nets` says each application copies the whole
   net; HeapModel's Functions paragraph makes a lazy application, a
   recipe cell that instantiates the frozen net and binds the argument.
   What decides it: in a lowered net, an application's argument is a
   live subnet, a box one level deeper, often sharing fans with the rest
   of the net. It is not a value.
   - *Splice:* copy the frozen net into the applying net where the leaf
     stood; beta binds the argument where it is, still lazy and shared.
     Levels must be offset (item 2).
   - *Recipe:* a new cell holds the copy and the argument, so the
     argument must leave the net first: forced, making glam strict where
     it is lazy, or extracted as a closed subnet, which is item 8.
   - *Both:* splice inside a net; a recipe only where the arguments are
     values already, the shell or a builtin applying a function.

   Recommended: both, splicing first. HeapModel's recipe then reads as
   the case of arguments that are values. Reframed by the maintainer's
   answer, below.

2. **The level offset on a splice.** A frozen function keeps its root's
   level in the bind's payload. Proposed: shift every level of the copy,
   of binds, applications and fans and each control's index, by the
   applying node's level minus the root's, as one control would
   (`V.lift_pay.b` already shifts each kind of payload). This answers
   HeapModel's open question of how pairing levels are offset when a net
   is copied into a running one, as NetPairing's comparison agreed: a
   template is instantiated at the level where it is applied. Two
   guards: a shift that would wrap a `U32` answers an error, since
   recursion through splices climbs a box at a time; and each splice
   takes a fresh instance for its fans, as `T.instantiate` does, so that
   `spike/net.bend`'s site check stays an assertion. The evidence is
   item 10's differential run.

3. **The protocol: `need`, and `splice` beside `resume`.** `need` gives
   the handle; a splice also needs the level of the node that met the
   leaf, at the path's top. Proposed: a splice loads the template into
   the frame's heap at fresh nodes, offset as item 2 says, wires the
   copy's root where the leaf stood, and walks on. The core splices every
   Func and lets the rules decide: beta for an application; an operator
   facing a bind is stuck, as an operator given a function is today
   (`net-error-values`), and reported so.

4. **Where live nets live.** Proposed: with one task forcing
   depth-first, every live net is a frame on the core's stack (`KD.D`),
   and the store holds only `Data`. That keeps Bend's affine arrays out
   of the store and the store within reach of laws. HeapModel keeps a
   suspended net in its cell instead, progress owned by no task (the
   Rust bootstrap's lazy-owns-partial-progress), which parallel rounds
   need. The migration is a frame moving into its cell as `Suspended`
   when sparks come.

5. **Freezing.** When demand ends with the root facing a bind, the nodes
   it reaches (`KN.reach`, then `KN.sweep`) are written out as a
   template: payloads read back from headers and the table, fans with
   their levels, controls with their index and shift, and each static
   link as the eraser it stands for, so that loading the frozen net
   gives the net frozen. That round trip is the first test. Before
   freezing, the net is reduced eagerly, as `copy-reduced-function-nets`
   says and the maintainer's answer below asks; this plan first deferred
   that, which would redo the pairs behind the bind in every copy.

6. **Recursion and cycles.** A function's net holds a leaf for its own
   cell, and each call splices a fresh copy as demanded, so recursion
   unfolds no further than demand reaches (`spike-fixpoints`: each call
   instantiating a compact template through a reference). Local
   recursive groups are lambda lifted by the front end, their captured
   locals made parameters, rather than making cells at run time (item
   8). A busy cell carries its owner, and a need is a strict cycle only
   when the busy cell is the needing task's own ancestor in the
   waits-for graph; with one stack every busy cell is, and once tasks
   come a need on another task's busy cell is a wait
   (`Heap_2026-11-09.md`, Fable's H1). Proposed: serve a cycle's need
   an error naming the cells around the cycle, so that each of them
   caches an error as its outcome. That is sound while errors cannot be
   caught; were they ever, catching one would observe divergence, which
   DistilledDesign rules out. A test needs no conditionals: Church
   booleans run today, and this terminating recursion, refused by the
   static linker now, would be the rung's hello sample:

   ```g
   language g0

   tt t e = t
   ff t e = e
   g b = b "Hello, World!" (g tt)
   asm.result = g ff
   ```

7. **Objects, and modules as objects.** Members are cells. An object's
   value is a dict whose entries hold handles, made before any member is
   forced, so `self` is a knot of handles and members are lazy with no
   mechanism beyond cells; a `_name` prior is a cell of its own; C3 linearizes the parents
   once per spec, at load. This serves objects declared at top level,
   and objects made at run time from closed definitions, by a request to
   the core for fresh cells, as a need is one. A member capturing a local
   waits on item 8. The object samples read so far (`hello_object.g`,
   `hello_object_expression.g`, `hello_object_prior.g`) capture none.

   The maintainer's direction (2026-11-09), planned before the move to
   Bend: modules become objects. A module is now an anonymous mixin,
   which lets `import` appear anywhere in a file but rules out multiple
   inheritance at module or project scope. A `.link` file stands for a
   remote module: a remote package is inherited concisely, and light
   tooling can update the remote links in a subtree without parsing the
   sources. Module imports (`ladder-imports`) wait for it. Asked: does
   `asm.result` become a member path of the assembly's object, the
   command line's files its parents?

8. **Laziness inside data made at run time: open.** A dict member
   computed in a running net has free variables wired into that net, and
   cannot become a cell until it is closed. Options:
   - *Strict members*, as today; laziness only where members are known
     at load (item 7).
   - *Lambda lifting the member*, which closes it but leaves its captured
     variables live subnets: a recipe would force them, or promote each
     to a cell in turn, the subnet extraction HeapModel left unsolved.
   - *Structures as nodes* (NetData's `netdata-structures`): dicts and
     lists as nodes, so laziness and knots stay inside the net, and a
     value leaving it is frozen.
   - *Cells at box boundaries:* a box's free wires are exactly what
     crosses it, so a box stored into data could be cut there, each
     crossing wire forced or promoted.

   The maintainer expects thunks and promises to be the hardest part;
   this is it. No recommendation yet. Strict members carry the samples
   read so far; the choice wants a design round of its own, after
   `cells-objects` shows what the samples need.

9. **Store and collection, for now.** An append-only table of `Data`
   cells, handles assigned in order, no collector: a batch assembly ends
   before its garbage matters. `store-pages` and `store-collection` stand
   for later.

10. **Laws and tests to aim at.** `glam/` has no laws yet; these would be
    its first.
    - Law: a cell only moves forward, Recipe to Busy to Value or Func,
      and its outcome is written once.
    - Law: after a resume, the leaf at the path's top holds the value;
      after a splice, the copy's root stands there at the applying
      node's level.
    - Test first, then perhaps a law: a frozen net loaded again is the
      net frozen, up to node numbering.
    - Test, not a law: a differential run. Every ladder sample, linked
      statically with today's linker kept as the oracle and run through
      cells, gives the same bytes and the same diagnostics.

## The maintainer's answers (2026-11-09)

- **Built-in imports** are compiler-local, presented as imports but not
  truly part of the module system; `import 'std` may come early
  (`builtin-imports-compiler-local`).
- **`self`.** In the Rust bootstrap an object's `self` was a promise,
  and `self.['foo]` could be a lazily evaluated thunk. How definitions
  are cells here wanted showing (below).
- **Item 1.** The bootstrap applied a function value with an operator,
  `ApplyArity`, which made a lazy application of it to its arguments.
  An application node meeting a function value was stuck, and only a
  raw net, with no arity, was spliced; both were materialized lazily by
  cursors, with no frozen net. Insisting on frozen nets forces maximal
  partial evaluation at every application step, eased by operators of
  higher arity (`ApplyK`) or by analysis of how many arguments a
  function takes before it is evaluated. The question arises only if
  `Ap >< Data(Fn)` is to be unstuck.
- **Item 2.** Try the proposed offset; proofs may be needed for
  confidence.
- **Item 3.** An experiment.
- **Item 4.** To discuss with the heap's model, for which the maintainer
  has alternatives in mind.
- **Item 5.** Freezing at weak head normal form redoes the active pairs
  behind the bind in every copy; the bootstrap's cursors shared that
  work. Without cursors, the obvious option is to evaluate the
  function's net eagerly, reducing every active pair.
- **Item 6.** May need reframing under item 1. A cycle reported as an
  error naming each step is essentially what the bootstrap did.
  Divergence may be observed only under reflection, not by evaluation.
- **Item 7.** Lazy evaluation of definitions is fine; the challenge is
  wiring `self` properly.
- **Items 8 and 9.** Revisited once the heap's model is discussed.
- **Item 10.** A good start.

## What the answers change

The agent's reading, for discussion.

- **Item 1 follows from the lowering.** The bootstrap could leave
  `Ap >< Data(Fn)` stuck because every application was an operator over
  values: its lowering compiles each argument lazily, as a thunk over
  its captured locals, and a local is a value there (the bootstrap's
  `src/g_syntax/net_lowering.rs` at 21912fc9). Here a local is a wire
  shared by fans at its level (`lowering-uses-levels`), so an argument
  is a live subnet, which an operator over values cannot take without
  forcing it or closing it (item 8). And a function value reaches an
  application node through any parameter: a global passed as an
  argument and applied by its callee. Under this lowering
  `Ap >< Data(Fn)` must be unstuck, and the splice that does it is the
  one a raw net needs anyway.
- **Item 5 as `copy-reduced-function-nets` has it.** A function's net is
  reduced eagerly under fuel before freezing, as the bootstrap's
  `anno 'jit` normalized a function at its first application. A pair
  needing a cell is left as it stands, since forcing it could unroll a
  recursion without end; each copy that demands it redoes it. Freezing
  comes once for each function-valued cell, never for each
  application: inside a net, `f a b c` is one splice and three betas,
  so evaluation at every step arises only where a partial application
  leaves its net as a value.
- **Item 6 under splicing.** Recursion is a need on a function cell, met
  by a splice. Eager reduction leaves needs alone, so a function's
  reference to itself is no cycle; only demand's need on a busy cell is
  one, its error naming each cell on the way.
- **Item 7, `self`.** As in the bootstrap, whose fixpoint hands its
  computation a reference to the lazy being forced (its
  `src/eval/value.rs`), an instance is a cell and `self` is its
  handle, given out before its value exists: a promise. Each member is a cell
  whose recipe applies the member's definition to `self` and its prior,
  both handles, so nothing is extracted from a net: a lazy application
  over values, item 1's other case. Composing the instance builds its
  dict of member handles without forcing a member, and `self.foo` reads
  it only when demanded. Late binding gives each instance its own cells
  for a definition it inherits, the template shared.

## Steps

1. `cells-review` — the maintainer reviews this plan; record what is
   decided in `docs/decisions/`.
2. `cells-data` — data-valued definitions as cells: handles assigned
   before lowering, a leaf per reference, the store, the core's stack
   forcing depth-first with `need` and `resume`. Behind a switch of the
   command line, the linker the default. `hello_names.g` through cells;
   the differential run over the ladder; interactions against the linker.
   - `cells-data.root` — built 2026-11-09 — root cells, as the
     re-scope has them: the values a template names, and those such
     values name in turn, each a cell of the book beside the templates,
     its handle after theirs; every other value linked as before.
     Demand meeting a cell's leaf forces its recipe on a task of its
     own, the task below set aside on one stack (each task a record of
     its demand, the cell it computes and the cell it waits on); a cell
     done resumes the task below with its value and keeps it. Its
     outcome no value, a function, the cell keeps its recipe and is
     spliced at each use as a template is: a stopgap until
     `cells-freeze`, the work of the first forcing not kept. A value
     that is a handle is an alias, chased at most as many hops as there
     are entries. asm.result's net done with its root facing a leaf is
     served as a need is. A need on a busy cell is a cycle, reported
     with the cell's name, as is a round of aliases. `--count` reports
     the interactions of every net, the splices and the values forced.
     Samples: `hello_cells.g` (13 interactions, 4 splices, 2 values
     forced, against 24 interactions linked) and the invalid
     `value_cycle.g`. Templates and recipes are lowered at start, so a
     form not lowered yet fails the assembly even in a definition
     nothing demands, as the desugarer reports every definition's
     errors; the linker dropped such a definition unread, a difference
     the differential run cannot see. Accepted by the maintainer
     (2026-11-10) so long as module loading is lazy
     (`unused-definitions-checked`). Not yet: a cycle's error cached in
     its cells and resumed into the net, as item 6 proposes; the cycle's
     other cells named; a function reaching asm.result reported as one
     (it now reads "asm.result has no value").
3. `cells-freeze` — a function-valued cell frozen: its net reduced
   eagerly under fuel, needs left alone; reach, sweep, the template
   written back with statics as erasers; the round trip over
   every ladder sample's net and the library's nets; the cost at n, 2n
   and 4n nodes.
4. `cells-splice` — a Func spliced at the applying node's level, fresh
   instances, the wrap guard; `hello_lambda_sugar.g` through cells; the

     lowering spliced where demand meets their leaves

     application that met it, so demand walks on from where it stopped
     (first built with the root, a bind, taking the leaf's slot; any root

     field's 24 bits; erasers made static as the loader makes them; a
     leaf met by an operator spliced unraised, stuck. Fresh instances are
     not needed: the kernel checks no fan's site. The lowering answers a
     pending name of a top-level function with a leaf

     `--link` the linker runs as before, and `scripts/ladder.py` checks

     `hello_names.g` 15 both ways, `hello_lambda_sugar.g` 20 against 35

5. `cells-recursion` — the linker's refusal lifted under cells: item 6's

## Cost

Each reference now costs a need and a resume: the demand loop returns
to the core, which reads the store and walks on. Each application of a
global function costs a copy of its frozen net. Every step measures
against the static linker in interactions, and in instructions where
they move; the kernel's spot workloads hold no handles and stay as they
are.

## Open questions

- What a `.link` file holds, and how it is named beside `.g` files: the
  remote's ref, revision and search list, as the remote import form has
  them now (`docs/Design.md`, Remotes).
- Partial data in a result: a text holding a handle, forced before
  output or reported.
- Inlining small definitions that need no cell, once a cell costs more
  than it shares.
