# Agent Notes

Blend is a preprocessor of static objects for Bend 2, written in Bend
(`blend.bend`): `.blend` files in, `.bend` files out, the objects gone.
It grew in glam-in-bend and is arranged as a repository of its own
(`blend-own-repository`). While it lives at glam-in-bend's `blend/`,
that repository's AGENTS.md governs everything around it; this file
governs Blend, and paths here are from Blend's directory.

## Reading

Required:

- `README.md` - the model, what Blend emits, the samples
- `docs/Decisions.md` - why things are as they are, indexing
  `docs/decisions/`
- `docs/plans/README.md` - how work proceeds, and the active plans

Contingent:

- When proving: glam-in-bend's `docs/Proving.md` (what the proofs so far
  have taught) and `docs/BendIssues.md` (Bend's shortfalls and their
  workarounds), and the lessons in `PROOF.bend`'s header
- When Bend is new to you: `bend guide`

## Layout

- `blend.bend` the tool; `LAWS.bend` what must hold of it, `PROOF.bend`
  the proofs, `MUTANTS.txt` the mutations each law must fail
- `samples/` executable specifications: each valid `.blend` beside the
  `.bend` Blend emits (generated: regenerate, never edit) and the `.out`
  it prints; `invalid/` beside the `.err` each must raise; `refused/`,
  emitted but refused by Bend
- `bench/` how Blend's cost grows with a module (its README)
- `docs/` decisions and plans
- `build.sh` builds Blend natively, once per version of it and of Bend;
  `run.sh` runs it; `where.sh` maps an emitted line back to its source
- `check.sh` the gate; `check_generated.sh` the generated samples;
  `samples/check.sh` the samples
- `tools.sh` finds the tools Blend shares with glam-in-bend (`capped.sh`,
  `count.sh`, `results.py`, `kept.py`, `one_law.py`, `check_docs.py`,
  `check_laws.py`): its own `scripts/` once split, else its parent's
- `results/` builds, copies and logs, out of git

## Working Rules

- Prefer narrow, testable slices: a focused sample before a broad fix.
  Valid, invalid and refused samples are the specification.
- A crash on user input is a bug, never semantics: a Bend fail-stop (a
  `Nat` past 2^48, a saturated count) reached from a `.blend` file is
  one too. Report an error instead.
- Blend translates objects and adds no Bend logic of its own
  (`blend-adds-no-bend-logic`).
- Generated files are regenerated by the tool that writes them, never
  edited; Python is a development tool, never the source.
- Record decisions in `docs/decisions/` when they are made; a leaning is
  not a ruling.
- Commits that advance a plan step end with `Plan-Step: <name>` trailers,
  before attribution lines. While Blend shares glam-in-bend's history,
  step names are unique across both projects.
- When removing a check, tell redundant work from a deliberate boundary.

## Laws

`LAWS.bend` states what must always hold of Blend; `PROOF.bend` proves
it. Agents write both.

- Comment each law with what it claims and the records it serves, as
  `# Record: <slug>`; a cited record must exist.
- On main, a commit that adds, changes or removes a law names it in a
  `Law: <name>` trailer. Develop law changes on side branches and land
  them with a `--no-ff` merge that names the laws.
- Never weaken, change or delete an existing law on main without the
  maintainer's explicit approval.
- A law weakened to be cheap lists its missing pieces in the plan beside
  it. Prefer state shapes in which an invariant holds by computation.
- Mutate the code a new law follows and keep the mutations in
  `MUTANTS.txt`: `one_law.py PROOF.bend LAW --mutants MUTANTS.txt`
  checks the law alone and tries them, as the gate does.

## Gate

Run `check.sh` before every commit to Blend: its docs, law history and
citations, proofs (rechecked by BendTT's kernel, `--verdict`), mutants,
generated samples, samples and Bend files, each section timed. A check
whose inputs are unchanged keeps its pass, never a failure. Report its
result as it is: a check skipped or too slow to finish is not a pass.
glam-in-bend's gate runs Blend's, and its pre-commit hook Blend's
generated check.

## Measuring

- Measure families at N, 2N and 4N (`bench/measure.sh SHAPE N`): one size
  hides superlinear growth. It records each run in the analysis store;
  cite run ids where a plan reports what they found.
- Instruction counts are signal; times are trend data, recorded with
  Bend's version, the commit and the CPU.
- Cap anything that may run away (`capped.sh MB SECONDS command`), near
  its normal cost: a hang is a fault to trace, not to wait out.

## The split

When Blend leaves glam-in-bend (`blend-home.split`): its shared tools
copied into `scripts/`, with the commit hooks; the lessons of
glam-in-bend's `docs/Proving.md` and `docs/BendIssues.md` it needs
copied into its `docs/`; its history filtered, and its records' revs,
which name glam-in-bend's commits, mapped or noted.
